# Решение проблем

## Проблемы с ботом

### Бот не отвечает на сообщения

**Симптомы:**
- Бот не реагирует на команды
- Сообщения не обрабатываются

**Решение:**
1. Проверьте, что бот запущен: `python bot/main.py`
2. Проверьте логи на наличие ошибок
3. Убедитесь, что токен бота правильный в `.env`
4. Проверьте интернет-соединение
5. Убедитесь, что нет нескольких экземпляров бота (может быть конфликт)

**Остановка всех процессов бота:**
```bash
# Windows PowerShell
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force

# Linux/Mac
pkill -f "python.*main.py"
```

### Ошибка "Update is not handled"

**Симптомы:**
- В логах появляется "Update id=... is not handled"
- Бот получает обновления, но не обрабатывает их

**Решение:**
1. Проверьте, что все роутеры зарегистрированы в `main.py`
2. Убедитесь, что обработчики правильно настроены
3. Проверьте порядок регистрации роутеров (fallback должен быть последним)

### Проблема с выбором типа мебели

**Симптомы:**
- При выборе типа мебели бот отвечает "Пожалуйста, следуйте инструкциям бота"
- Не переходит к следующему шагу

**Решение:**
✅ **Исправлено!** Fallback обработчик теперь исключает состояние `choose_item_type` с помощью фильтра `~StateFilter(OrderStates.choose_item_type)`.

Если проблема повторяется:
1. Проверьте, что `fallback.py` использует фильтр `~StateFilter(OrderStates.choose_item_type)`
2. Убедитесь, что `order.py` зарегистрирован перед `fallback.py` в `main.py`
3. Проверьте логи - должно быть видно, какой обработчик срабатывает

### Ошибка "CHANNEL_ID не установлен"

**Симптомы:**
- При попытке опубликовать кейс или пост появляется ошибка
- В логах: "CHANNEL_ID не установлен в конфигурации"

**Решение:**
1. Добавьте `CHANNEL_ID` в файл `.env`:
   ```env
   CHANNEL_ID=-1001234567890
   # или для публичного канала
   CHANNEL_ID=@your_channel_username
   ```
2. Перезапустите бота
3. Убедитесь, что `.env` файл находится в корне проекта (не в `bot/`)

### Ошибка "Chat not found" при публикации

**Симптомы:**
- При публикации в канал появляется ошибка "Chat not found"

**Решение:**
1. Убедитесь, что бот добавлен в канал как администратор
2. Проверьте правильность `CHANNEL_ID`:
   - Для приватного канала используйте числовой ID (например, `-1001234567890`)
   - Для публичного канала можно использовать `@username`
3. Убедитесь, что у бота есть права на публикацию сообщений

### Ошибка "Not enough rights"

**Симптомы:**
- При публикации появляется ошибка "Not enough rights"

**Решение:**
1. Откройте настройки канала
2. Перейдите в "Администраторы"
3. Найдите бота в списке
4. Убедитесь, что у бота есть права:
   - ✅ Post messages (публикация сообщений)
   - ✅ Edit messages (редактирование сообщений, опционально)

### Фото не отображаются в админ-панели

**Симптомы:**
- В админ-панели фото не загружаются
- Показывается ошибка или пустое место

**Решение:**
1. Проверьте, что токен бота правильный
2. Убедитесь, что `file_id` в базе данных актуальны
3. Проверьте интернет-соединение
4. Убедитесь, что бот имеет доступ к файлам (не был удален из чата)

**Примечание:** `file_id` в Telegram действительны ограниченное время. Для долгосрочного хранения рекомендуется сохранять файлы на диск.

## Проблемы с админ-панелью

### Админ-панель недоступна

**Симптомы:**
- Не открывается http://localhost:5000/admin
- Ошибка подключения

**Решение:**
1. Убедитесь, что бот запущен
2. Проверьте, что порт 5000 не занят другим приложением
3. Проверьте логи на наличие ошибок Flask
4. Попробуйте изменить порт в `.env`: `ADMIN_PORT=5001`

### Ошибка 500 при открытии страницы

**Симптомы:**
- Админ-панель открывается, но показывает ошибку 500

**Решение:**
1. Проверьте логи Flask в консоли
2. Убедитесь, что база данных существует и доступна
3. Проверьте права доступа к файлу базы данных
4. Попробуйте пересоздать базу данных (удалите `bot.db` и перезапустите бота)

## Проблемы с базой данных

### Ошибка "database is locked"

**Симптомы:**
- В логах появляется ошибка "database is locked"
- Операции с БД не выполняются

**Решение:**
1. Убедитесь, что нет нескольких экземпляров бота
2. Проверьте, что база данных не открыта в другом приложении
3. Перезапустите бота
4. Если проблема повторяется, проверьте права доступа к файлу БД

### База данных не создается

**Симптомы:**
- Файл `bot.db` не создается
- Ошибки при работе с БД

**Решение:**
1. Проверьте права на запись в директорию `bot/`
2. Убедитесь, что путь к БД правильный в `.env`
3. Проверьте логи на наличие ошибок при инициализации БД

## Проблемы с зависимостями

### ModuleNotFoundError

**Симптомы:**
- Ошибка "No module named 'aiogram'" или подобная
- Импорты не работают

**Решение:**
1. Убедитесь, что виртуальное окружение активировано
2. Установите зависимости: `pip install -r bot/requirements.txt`
3. Для Python 3.13 убедитесь, что используете aiogram 3.23.0 или выше
4. Обновите pip: `pip install --upgrade pip setuptools wheel`

### Ошибки при установке aiogram

**Симптомы:**
- Не удается установить aiogram
- Ошибки компиляции

**Решение:**
1. Обновите pip: `pip install --upgrade pip setuptools wheel`
2. Для Python 3.13 используйте aiogram 3.23.0+ (готовые wheels)
3. Убедитесь, что используете актуальную версию Python
4. Попробуйте установить без кэша: `pip install --no-cache-dir aiogram`

## Проблемы с развертыванием

### Бот не запускается автоматически

**Симптомы:**
- После перезагрузки сервера бот не запускается
- systemd не запускает сервис

**Решение:**
1. Проверьте статус сервиса: `sudo systemctl status peretiazhkoff-bot`
2. Проверьте логи: `sudo journalctl -u peretiazhkoff-bot -n 50`
3. Убедитесь, что сервис включен: `sudo systemctl enable peretiazhkoff-bot`
4. Проверьте пути в файле сервиса (должны быть абсолютные)
5. Убедитесь, что у пользователя есть права на выполнение

### Бот падает с ошибкой

**Симптомы:**
- Бот запускается, но затем падает
- В логах ошибки

**Решение:**
1. Проверьте логи: `sudo journalctl -u peretiazhkoff-bot -n 100`
2. Убедитесь, что все переменные окружения установлены
3. Проверьте права доступа к файлам
4. Убедитесь, что база данных доступна
5. Проверьте интернет-соединение

## Общие рекомендации

1. **Всегда проверяйте логи** - они содержат важную информацию об ошибках
2. **Используйте виртуальное окружение** - это изолирует зависимости
3. **Проверяйте .env файл** - убедитесь, что все переменные установлены
4. **Не запускайте несколько экземпляров** - это может вызвать конфликты
5. **Регулярно обновляйте зависимости** - для безопасности и совместимости
